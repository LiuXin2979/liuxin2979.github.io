一轮齿轮测量会留下去程和回程两串读数。主轴回到同一个角度时，从轴的位置可能不同。把两段数据放到同一条主轴角度轴上，再比较从轴位置，就能看出这段差异在整个测量区间里如何变化。下面以 C# WinForms 上位机为例，从读卡讲到这条曲线是怎样算出来的。

## 1. 编码器位置和扭矩从哪里来

主轴与从轴各有一个编码器。轴转动时，编码器把位置变化转换为电信号，IK 220 计数卡处理这些信号，Windows 驱动再通过厂商 DLL 把位置值交给上位机。IK 220 每张卡最多可接两路编码器，本项目按接线配置支持主从轴在同一张卡，也支持分别接在两张卡上。[HEIDENHAIN 产品说明](https://www.heidenhain.com/products/encoders/signal-converters/computer-aided-measurement)

| 数据来源 | 上位机读取的内容 | 用途 |
| --- | --- | --- |
| IK 220 计数卡 | 主轴和从轴的位置值 | 对齐去程与回程，计算间隙曲线 |
| PLC 快照 | 扭矩、工件状态及本轮身份 | 校验测量过程，计算整轮扭矩波动 |
| 机型参数 | 有效区间、换算与标定参数、判定限值 | 把位置差换算成间隙并生成判定 |

## 2. 先确认读的是哪张卡、哪根轴

上位机以 Windows x86 进程运行，通过 C# 的 P/Invoke 调用 32 位 `IK220Dll.dll`。驱动访问集中在一层适配器里。实际 DLL 和测试用假驱动实现同一套接口，因此测量代码可以用模拟读数验证异常分支。

1. **枚举与绑定**。调用 `IK220Find` 取得逻辑轴和驱动地址。程序把同一块卡上两个轴的地址组合成绑定标识，用它核对配置。这个标识依赖当前设备枚举，换槽或换卡后需要重新核对。跨卡采集会分别核对主轴和从轴所在的卡。
2. **初始化与清零**。绑定核对通过后，对尚未初始化的轴调用 `IK220Init`。每轮采集前调用 `IK220WritePar` 设置编码器输入信号类型，再分别调用 `IK220Reset` 清零，建立本轮的位置基准。
3. **读取与复核**。采样时调用 `IK220Read48`。适配器把原生调用和 DLL 状态读取放在同一把进程级锁内，采样期间定期复核板卡拓扑。设备缺失、绑定不符或已建立的拓扑发生变化时，本轮停止采集，待核对后重新建立硬件会话。[IK 220 用户手册](https://product.heidenhain.de/JPBC/image/HWP.EN/hlr-system/ik220_de-en.pdf)

`IK220Read48` 的 C 接口把 48 位计数读数写入一个 `double` 输出参数。C# 声明中用 `ushort` 对应轴号和寄存器参数，用 `out double` 接收位置值。这个值沿用驱动单位，工程量换算由测量层完成。[IK 220 用户手册，IK220Read48](https://product.heidenhain.de/JPBC/image/HWP.EN/hlr-system/ik220_de-en.pdf)

```csharp
[DllImport("IK220Dll.dll", EntryPoint = "IK220Read48",
    CallingConvention = CallingConvention.StdCall, ExactSpelling = true)]
private static extern int Read48(ushort axis, ushort register, out double position);
```

## 3. 一条样本怎样组成

每次采样先读主轴，再读从轴。程序用单调计时器记录两次读调用完成时刻的间隔，并保存位置样本的 UTC 时间。这个间隔用来排查驱动调用变慢等问题。两轴在软件里顺序读取，实际采样时差还需在设备上测量。

扭矩取自采样循环拿到的 PLC 快照。程序检查这份快照是否仍在有效时间内，并保留扭矩自己的时间戳。主轴有效位置变化时才追加样本，所以原始记录能同时反映两轴读数、读取间隔和扭矩的有效性。位置非有限、工件身份变化、掉线或采集超时都会中止本轮。现场测量根据主轴位置与停留条件判断去程、折返和结束。

## 4. 在同一主轴角度比较两条曲线

去程和回程的采样时刻与点数可能不同。程序从时间序列的两端提取去程和回程，把回程倒过来，再用主轴角度作横坐标、从轴位置作纵坐标。随后选取有效区间和落在目标网格上的样本。同一方向的重复角度保留首次遇到的读数。两段数据在共同覆盖的等步长角度网格上分别做线性插补。

用一组虚构读数举例。假设两个方向都缺少主轴 **30°** 的读数，可以分别用两侧实测点补齐。

| 主轴角度 | 去程从轴位置 | 回程从轴位置 |
| --- | --- | --- |
| 20° | 100 | 116 |
| 30° | 120（线性插补） | 132（线性插补） |
| 40° | 140 | 148 |

在 **30°** 这个位置，换算前的差值是 `|120 − 132| = 12` 个示例位置单位。对每个角度重复同样的计算，就得到一串位置差。项目再做归一化、边缘处理和中值滤波，按机型的比例与标定参数换算成间隙曲线。样本太少、方向数据不单调或输出区间覆盖不足时，计算会报错。

| 指标 | 计算方式 |
| --- | --- |
| M1 | 间隙曲线最小值 |
| M2 | 间隙曲线最大值 |
| M3 | 间隙曲线极差，即 M2 − M1 |
| N1 | 整轮有效扭矩的最大值减最小值 |

如果某个保留点缺少有效扭矩，离线复算仍能显示间隙曲线，N1 标记为无效，整轮不能判为合格。在线测量先保存原始数据与结果，再向 PLC 提交，并分别记录本地保存和提交状态。

## 5. 怎样离线验证

离线演示和 TDMS、CSV 回放复用同一套计算逻辑。用合成样本可以检查去回程覆盖不足、扭矩缺失等情况。板卡接入层则用假驱动复现读卡失败、主从轴绑定错误和拓扑变化。也可以用同一份样本重跑，逐点比较调整前后的间隙曲线和四项指标。

现场验收还需核对板卡与接线、编码器信号类型、读取时差、PLC 通信、机型标定和判定限值。项目页记录了整体功能与验证范围。[齿轮间隙测量系统](/projects/gear-backlash-measurement/)

如果想看另一种公开的齿隙测量实现，Robonine 的开源试验台展示了双向加载、遥测记录与结果分析的完整流程。[UART 伺服齿隙测量台](https://github.com/roboninecom/Measuring-Backlash-in-Popular-UART-Servos)
