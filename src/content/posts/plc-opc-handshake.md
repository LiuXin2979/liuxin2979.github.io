## 请求与结果使用同一个标识

在离线模拟器里设计一组虚构信号。模拟 PLC 先写入请求内容和 `RequestId`，再置位 `RequestValid`。处理方读取完整快照，校验请求号与数据质量，并把业务处理与这次请求关联。处理完成后回写 `AckId`、结果码及 `AckValid`。请求侧只有在两个 ID 匹配时才接受结果。

```text
请求方                         处理方
准备数据，置位 RequestValid  →  读取并校验请求快照
等待 AckValid 与 AckId       ←  写入轮次及处理结果
确认轮次后清除 RequestValid   →  清除 AckValid
```

若 OPC 把各字段作为独立点位读取，字段更新可能跨越不同采样周期。模拟端可以约定提交标志和读取期间的序号复核。有条件时，用双方已验证的结构化快照统一传输。发现数据质量无效或序号变化时，保留等待状态并记下原因。

## 重复信号和断线都要演练

- **同一请求反复出现**。去重使用稳定的来源与请求标识。若业务结果和去重标记保存在同一个数据库，尽量在同一个事务写入。确认丢失后可重发已持久化结果。
- **旧应答迟到**。模拟请求方重启并开启新会话，验证上一轮结果无法完成新请求。短计数器回绕和重启后的 ID 重用需要在标识约定中单独处理。
- **OPC 中途断开**。重连后先核对连接质量、请求号和双方阶段，再恢复处理。超时进入可观察的状态，并保留当前轮次供诊断。

这组点位、顺序和结果码用于讲解。实际 PLC 扫描周期、OPC 更新模式与 MES 重试规则需要由双方用协议和记录验证。

参考 [OPC Foundation 的 DataValue 结构与状态码说明](https://reference.opcfoundation.org/specs/OPC-10000-4/7.11)。
